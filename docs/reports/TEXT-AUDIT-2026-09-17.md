## 2. 发现的问题（按严重度）

> **编号约定**：本轮发现一律用 **`T`**（Text audit）前缀，**不得用 `A` / `B` / `C` / `D` / `E` / `N` / `S`** ——
> 那些前缀在 `docs/AUDIT-BACKLOG.md` 里**已被历史批次占用且含义不同**（例如台账的 `A3` 是「签名定级缺口」，
> 与本报告无关）。落账时两边编号必须一致，否则同一个 `A3` 会指两件事。

### 🔴 T1 · `architecture.md:147` 规则数仍是错的 27

- **位置**：`docs/architecture.md:147` 里程碑映射表 →「M3 规则引擎 | **27 条** AST 硬规则 + LangGraph 双轨」
- **实测**：`worker/rules.cjs` 的 `RULE_TABLE` = **25 条具名 + `unknown` 兜底**

  **根因**：S4 是按精确短语 `27 条查表规则` 去改的，而这两处写的是 `27 条 AST 硬规则` / `27 条确定性规则`
  —— **措辞不同就漏了**。与「改 A 的措辞要回查 B 的引用」是同一族病。

## 3. 审计手法复盘（本轮自身翻过的车）

审计者也会犯被审计的错误。本轮我自己的脚本出过 **4 次**同类错，全靠"写完就量一遍"抓住：

| # | 我写下的 | 实测 | 错法 |
|---|---|---|---|
| 1 | 「e2e-logs 49 个文件 / 5+ 命中」 | **45 个 / 12 个命中** | 写完没量 |
| 2 | 「scripts 里有 coverage」 | **没有**（`some()` 恒真，探针 bug） | 表达式写错还照报 |
| 3 | 「`npm test` 的 script 不存在」 | **存在**（剥离前缀的 bug） | 逻辑 bug |
| 4 | 用 `grep -E '\{2,\}'` 搜常量 → 返回 0 命中 | **确实存在** | toybox grep **区间量词静默失效**；换 Grep 工具才搜到 |

**教训**：`搜不到 ≠ 不存在`；**任何数字先量再写**；校验工具本身也要被校验。
