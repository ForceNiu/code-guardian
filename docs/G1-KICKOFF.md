## 一 · 这个项目是什么（新对话需要的全部背景）

**code-guardian** —— 一个**代码副作用检测平台**。仓库 `ForceNiu/code-guardian`（公开，MIT）。

**它解决的问题：改一个函数，谁会受影响？**

常规 CI 只会告诉你"测试挂了几条"。它给出的是**影响清单**：哪些文件被波及、每一处是 breaking 还是兼容、
依据是什么（确定性规则还是 AI 判定）。

工作链路（**已全部打通**）：

| 阶段 | 做什么 |
|---|---|
| 接入 | 接 GitHub / GitLab webhook，推代码时自动触发 |
| 调度 | 任务入队、并发上限 3、超时 300s、崩溃后回收 |
| 分析 | 拉仓库 → 解析 AST → 比对改动前后的导出符号 → 沿 import 链算**影响图** → 规则引擎定级 |
| 兜底 | 规则归不了类的变更，交 **AI 语义引擎**（LangGraph + DeepSeek）判定 |
| 呈现 | 网页上看风险总览 + 影响链路表 + 并排代码 diff；进度用 SSE 实时推 |
| 回写 | 把结论写回 GitLab 的 Commit Status |

**技术栈**：Next.js 16 · React 19 · TypeScript · Prisma + Postgres（Neon）· LangGraph + DeepSeek · Vercel · GitHub Actions

**当前状态**：功能闭环、工程完备 —— 238 个单测 / 4 道 CI 门禁 / 86 个入库文件 / 12 份文档。

## 二 · G1 要做什么

**一句话**：一份**给完全不懂代码的人看**的 HTML 单页，讲清"这个工具是干什么的、解决什么痛、凭什么做得出来"。

### ⚠️ 开工第一步是「重新对齐范围」，不是动手写

原始范围定义**已随 `HANDOVER.md` 丢失**，全仓只剩 `docs/AUDIT-BACKLOG.md` §二 第 4 条的一句摘要：

> 范围早已锁定（**功能 + 架构两层里的第一层**，HTML 单页，全真口径），未开工。

所以开工第一件事：**先出一份提纲给用户过**，确认这三件事 ——

1. **读者是谁**：面试官 / 非技术的合作方 / 自己复习用？（决定用词深浅）
2. **只做"功能层"，还是这轮连"架构层"一起**：原文写的是"两层里的第一层"，即先只做功能层
3. **要不要交互**：纯图文？还是带可点的演示（比如展开一条影响链看它怎么算出来）

**别跳过这一步直接产 HTML。** 范围原件已丢，任何"我记得应该是……"都是猜测。

## 四 · 学习部分（借这个项目练什么）

"写说明书"和"学习"可以是一次动作的两面 —— **写说明书要求真懂，讲不清就是没懂**。

> ✅ **学习取向已选定：`a · 讲清系统`**（2026-09-17 定）。
> b（Next.js / React / TS）、c（工程方法论）本轮不做，以后可回头补 —— 不必在 G1 期间并行。

| 取向 | 练什么 | 和 G1 的关系 | 本轮 |
|---|---|---|---|
| **a · 讲清系统** | 把复杂系统讲给外行听：抓主线、砍枝节、用类比 | **完全重合** —— 写说明书就是练习本身 | ✅ **已选** |
| b · Next.js / React / TS | 补技术短板（React 零经验、TS 自评零） | 需另开路径：读源码 + 逐轮讲解 | ⏸ 以后 |
| c · 工程方法论 | 测试纪律 / 越权边界 / 回归验证 | 部分重合（G1 会用到"事实来自代码"这套） | ⏸ 以后 |

**选 a 的学练节奏（硬性）**：每写完一节，**合上文档、用自己的话讲一遍**（不看着念）——
讲不顺的地方，就是那一节要重写的地方。**这一步不能省**：跳过它，G1 就退化成"把 README 翻译成大白话"，
而练不到"讲清系统"本身。

**讲的对象**（按上面「开工第一步是『重新对齐范围』」那一节确认的读者来定，默认先按"非技术读者"练）：
讲的时候假设对方**不懂任何技术词**，一旦你嘴里蹦出"API / 依赖 / 编译"这类词而没当场类比，就说明这节没讲透。
